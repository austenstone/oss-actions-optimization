Optimizing GitHub Actions across open source

AI agents scan busy public repos, measure where Actions minutes go, and send small PRs that cut the waste. Every number on this page comes from public run history.

How it works

FindShortlist the busiest public repos and their heaviest workflows.
MeasurePull real runs, jobs and step timing from the public Actions API. Separate queue time, wall clock, job minutes and waste.
FixPick the single strongest finding and write the smallest diff that removes it. Fail open: when in doubt, run everything.
ShipTest on a fork where possible, then open a short PR that follows the repo's template.

The agents follow the public actions-optimization skill.

Rules we hold ourselves to

  • Structural waste over red builds. A workflow that mostly fails needs a diagnosis, not a CI tweak. Failing PR runs are often CI doing its job.
  • Measured vs estimated, always labeled. "Measured" numbers come from a stated window of real runs. "Estimated" numbers project those measurements forward.
  • Don't change what the project means to test. Changes that alter coverage on purpose (stacked PRs, release cadence) go to maintainers as findings, not PRs.
  • Short PRs. Problem, fix, how it was tested. Let the diff do the talking.
  • Minutes, not dollars. Public repos run free on standard GitHub-hosted runners. The win is runner capacity and faster queues for everyone.
